## TRL 1.14.2 / transformers 5 (training job, verified 2026-11-12 from the installed wheels)
- `DPOConfig` has no `max_prompt_length`; `max_length` truncates prompt+completion with `truncation_mode="keep_start"`
  (only supported value), i.e. it cuts the end of the reply. `train.py` drops pairs with prompt > 2688 or
  prompt + longer reply > 3072 tokens instead (same pairs for D/E/R); count in `train_manifest.n_dropped_long`.
- `TrainingArguments.warmup_ratio` is gone (transformers 5.x); `warmup_steps: float` accepts a value in [0, 1)
  as a ratio of total steps. `train.py` passes `warmup_steps=0.1`.
- `precompute_ref_log_probs` exists (default False); `padding_free` falls back to padding in 1.14.

## vLLM greedy decoding is not reproducible run to run (measured 2026-11-12)
Same adapter (E), same 16 conversations, two jobs with different batch composition (16 against 456 conversations):
15 of 16 first replies differ, mean shared prefix 38% of the reply, 3 of 68 turn labels differ. Cause: bf16
arithmetic depends on the batch; a near-tie flips and the continuation diverges. Consequences: published hashes
cannot be regenerated by a replay; differences of a few conversations between conditions are within run-to-run
noise; report paired intervals, and repeat the base run to measure the noise when the budget allows.
